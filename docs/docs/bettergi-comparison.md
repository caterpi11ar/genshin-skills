# BetterGI 对标与路线

本页基于 2026-08-07 的 BetterGI 官方 README、当前 giclaw 代码审计与真实账号验收。两者运行环境不同：BetterGI 控制 Windows 本地客户端并使用专用计算机视觉；giclaw 控制云原神网页并借助通用视觉模型。因此应对标用户价值和可靠性机制，而不是机械复制每个本地客户端功能。

## 当前可用性结论

giclaw 的配置、技能加载、依赖编排、任务调度、持久化和 Web/TUI 控制链已形成闭环，并有自动化测试覆盖关键编排规则。月卡、邮件、纪行、成就和活动奖励 5 个任务已在真实账号环境完成全流程验收。探索派遣当前暂停，尚未完成领取与再次派遣闭环。

本轮审计前的主要阻断点已经修复：空步骤不再被当作成功，未知任务不再静默忽略，技能上下文会真正进入模型，`--no-headless` 会贯穿 Cookie 恢复流程，队列上限生效，失败会记录现场截图，重试也会由失败异常正确触发。

## 能力矩阵

| 能力 | BetterGI | giclaw 当前 | 判断 |
|---|---|---|---|
| 视觉驱动、模拟输入 | 专用 CV + Windows 输入 | 通用 VLM + Playwright | 路线不同，均不读游戏内存 |
| 日常一条龙 | 成熟脚本调度 | routine + 技能依赖 | 编排地基已具备，技能覆盖仍少 |
| 键鼠录制/回放 | 有录制器和脚本 | 12 个确定性键鼠原子操作 | 可写回放脚本，尚无录制 UI |
| 自动拾取/剧情 | 高频实时识别循环 | 无常驻帧循环 | 关键缺口 |
| 快速传送/地图寻路 | 小地图定位与路径追踪 | 仅能让通用 VLM 操作地图 | 稳定性差距较大 |
| 战斗/秘境/地脉 | 专用识别、队伍和战斗策略 | 无 | 不宜直接用慢速 VLM 硬做 |
| 钓鱼/音游/烹饪 | 专用实时算法 | 无 | 需要低延迟本地视觉模块 |
| 奖励领取 | 多种一条龙脚本 | 月卡、邮件、纪行、成就、活动 | 5 项均已完成真实账号验收 |
| 探索派遣 | 支持收取与重新派遣 | 能力定义保留 | 当前暂停，未进入稳定回归集 |
| 调度与控制面 | 脚本调度器、遮罩日志 | cron、FIFO、TUI、Web、WebSocket | giclaw 已有服务化优势 |
| 失败诊断 | 图像识别结果与日志 | transcript + 自动失败截图 | 已具备基础，仍缺可视化回放 |

## 本轮落地

1. 原子操作从 6 个扩展为 22 个：10 个视觉操作和 12 个确定性键鼠/诊断操作。
2. 新增 `dependsOn`，自动递归加入前置任务、去重和检测依赖环。
3. 新增 `daily`、`rewards`、`full` 命名流程和 `--routine`。
4. 新增默认关闭的成就奖励、活动奖励任务，并把原有纪行/派遣从空工作流迁移为可执行 Steps。
5. 技能目录支持用户同 ID 覆盖内置技能；严格拒绝空步骤、未知操作、错误 ID 和未知依赖。
6. `Background` / `Goal` / `Known Issues` 正式注入视觉 Agent。
7. 修复 headless 配置、模型 provider family、任务超时计时器、失败重试和队列深度。
8. 每次失败自动截图并把路径写入 transcript；`aiBoolean` 结果也会被记录。
9. `@midscene/web` 依赖升级到 `1.10.9`；当前模型链继续使用 Chat Completions，并在项目内完成流式响应聚合，没有接入 Responses API。

## 推荐后续优先级

### P0：持续回归与安全护栏

- 为 5 个已通过任务建立版本化截图回归集和持续账号验收清单；暂停能力单独管理，不混入稳定回归集。
- 给领取类操作增加“禁止购买、禁止消耗原石”的统一策略层，而不是依赖每个 prompt 重复说明。
- 增加失败后的恢复步骤（回主界面、关闭弹窗）和可配置的 `continueOnError`。
- 对模型 API 做启动诊断命令，区分配置有效、模型支持图像、实际游戏成功三个层次。

### P1：BetterGI 式录制器与可视化回放

- 在可见浏览器中记录 Playwright 键鼠事件，导出为现有确定性 Steps。
- Web 面板展示逐步截图、耗时、AI 布尔结果和失败步骤，并允许从指定步骤重放。
- 为固定分辨率动作加入视口基准和坐标缩放，避免宏只适用于 1280×720。

### P2：低延迟实时引擎

- 单独实现定频截图、ROI 裁剪、模板/OCR 检测和节流输入，不通过每帧 VLM 请求。
- 先做自动对话和自动拾取这类状态机清晰的能力，再评估钓鱼、音游。
- 实时引擎与当前 workflow 引擎通过统一原子操作和安全策略协作。

### P3：地图与战斗

- 引入小地图定位、航向估计、路径资产和卡住恢复，才能可靠实现采集/地脉。
- 战斗需要独立的角色配置、技能循环、目标检测和超时退出模块，不应塞进通用 `aiAct`。

## 风险提示

视觉识别和模拟输入不等于零风险。第三方自动化可能违反游戏服务条款，也可能因 UI 更新、分辨率、网络和模型误判执行错误操作。已验收不代表未来版本永久稳定；UI 或模型变更后的首次回归建议使用可见模式观察，并避免任何付费或不可逆操作。
